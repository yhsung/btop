# P3 runner + wiring + sink Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `btop-runner` crate: AppState assembly, full Action sink, and a single-threaded tick with output merge, plus detail/tree/filter golden upgrade.

**Architecture:** New workspace member `btop-runner` (zero third-party deps; path deps on collect/draw/input/menu/config/tools). `wiring.rs` assembles draw inputs from AppState + collector outputs (pure, headless tests); `sink.rs` executes every Action against an explicit World with trait-injected syscalls (fake doubles in tests, zero real syscalls); `tick.rs` runs schedule→collect→draw→merge→string with fake backends in tests.

**Tech Stack:** Rust 2021, `cargo test`, C++ harness extension for 3 scenarios.

**Spec:** `docs/superpowers/specs/2026-09-06-runner-p3-design.md`

## Global Constraints

- Zero third-party dependencies (path deps on workspace crates only).
- `cargo test --workspace --locked --offline`, `cargo clippy --workspace -- -D warnings`, `cargo fmt --check` green after every task.
- Transcribe C++ branch order/flags verbatim from cited `src/btop.cpp` lines; deviations need a comment + report.
- No threads/semaphores/pthreads (single-threaded by decision); no signal installation, CLI, locale, Term init, or fd reading (P4 owns all of those).
- Zero real syscalls under `cargo test` (kill/setpriority/term writes go through injected doubles).
